Panoramica

Questo documento descrive le specifiche funzionali e tecniche delle tre aree del modulo IDM (Identity Management): Utenti, Funzionalità e Ruoli & Permessi. Le specifiche sono ricavate per reverse engineering dal codice sorgente e dagli screenshot dell'applicazione originale.

Utenti

Lista paginata, filtri avanzati, assegnazione ruoli tramite modal multiselect.

Funzionalità

Albero gerarchico configurabile: categorie e funzionalità, drag&drop, multilingua.

Ruoli & Permessi

RBAC: creazione ruoli, assegnazione permessi per funzionalità tramite albero con toggle.

Stack Tecnologico dell'Originale

LayerTecnologia
DatabasePostgreSQL — schema parametrico (default: iam)
BackendJava 17 / Spring Boot — API REST generata da OpenAPI spec
FrontendNext.js (React) con React Query per la gestione dello stato async
AuthJWT Bearer Token — l'IDP esterno emette il token; il backend lo valida
API Base URLConfigurabile — es. https://api.example.com

Frontend — Pagina Utenti

Route: /userManagement  ·  Titolo pagina: "Gestione utenti"

Layout Tabella

  • Colonne visibili di default: Utente (firstName + lastName), Email, Data di creazione, Ruoli, Stato, Ultimo aggiornamento
  • Tutte le colonne sono ordinabili cliccando l'intestazione; freccia indica direzione (ASC/DESC)
  • La colonna Ruoli mostra i nomi separati da virgola (es. "Administrator, Card viewer, Registered user")
  • La colonna Stato mostra un badge colorato: Attivo (verde) / Disattivato (grigio)
  • La colonna Ultimo aggiornamento mostra tempo relativo (es. "1 anno fa", "4 mesi fa")
  • Ogni riga ha un menu ⋯ (tre puntini) con l'azione "Gestisci Ruoli"

Barra superiore (toolbar)

  • Search input (sinistra): placeholder "Cerca" — filtra per nome e email, ricerca con debounce
  • Pulsante "Colonne": apre un pannello per mostrare/nascondere colonne
  • Pulsante "Filtri": apre un drawer laterale con filtri avanzati:
    • Multi-select Ruoli (lista da GET /role/all)
    • Multi-select Stato (Active / Deactivated)
    • Date range picker (Data di creazione: da ... a ...)

Paginazione

  • Paginazione numerata in fondo: [1] [2] [3] [...] [N] [›]
  • La pagina corrente è evidenziata

Modal "Gestisci Ruoli"

  • Aperto dal menu ⋯ → "Gestisci Ruoli"
  • Titolo: "Gestisci Ruoli"
  • Sottotitolo: "Stai gestendo i ruoli di [firstName] [lastName] ([email])."
  • Campo "Ruoli": dropdown multi-select con checkbox per ogni ruolo disponibile
  • I ruoli già assegnati all'utente sono pre-selezionati (caricati da GET /user)
  • La lista dei ruoli disponibili viene da GET /role/all
  • Bottone "Conferma" → POST /user/role con l'intera lista aggiornata → chiusura modal → refresh tabella
  • Bottone "Annulla" → chiude senza salvare

Area: Funzionalità

Configuration

Gestione dell'albero delle funzionalità del prodotto. L'albero è gerarchico (categorie + funzionalità) e definisce sia la navigazione del prodotto sia gli oggetti su cui il sistema RBAC assegna i permessi.

L'albero ha due root virtuali: root (id_item = 0) per le sezioni principali e operations (id_item = -1) per i permessi tecnici/operativi. Ogni root rappresenta un tab distinto nell'UI.

/configuration/navigation_tree/{root}/subtree
Albero completo a partire da una root. root = nome letterale (es. root, operations).
Admin

Recupera un singolo nodo (per pre-popolare il form di modifica)
Admin
POST
/configuration/navigation_tree/item
Crea un nuovo nodo (categoria o funzionalità)
Admin
PATCH
/configuration/navigation_tree/{itemId}
Aggiorna un nodo esistente
Admin
POST
/configuration/navigation_tree/{itemId}/move
Sposta un nodo nell'albero (drag&drop o cambio genitore)
Admin
DELETE
/configuration/navigation_tree/{itemId}
Elimina un nodo (ricorsivo sui figli)
Admin
GET
/configuration/parentList
Lista dei nodi utilizzabili come genitore (per il dropdown "Genitore" nel form)

Frontend — Pagina Funzionalità

Route: /functionalities  ·  Titolo: "Funzionalità"

Vista Albero (index)

  • Barra superiore: Search input (300px, icona lente, placeholder "Cerca") a sinistra; pulsante "Crea nuovo" + (opzionale) pulsante "Batch Patch" a destra
  • Tabs: una per ogni root dell'albero — il tab root è etichettato "Tutto"; altri tab dalla loro traduzione
  • L'albero mostra la gerarchia con indentazione; i nodi sono espandibili/collassabili
  • Ogni riga ha un handle ⠿ per il drag&drop di riordinamento
  • Nodo CATEGORY (icona + sfondo): azioni + (crea figlio), ✎ (modifica), 🗑 (elimina)
  • Nodo FUNCTIONALITY: azioni ✎ (modifica), 🗑 (elimina)
  • Drag&drop chiama POST .../move con la nuova posizione
  • Elimina con modal di conferma → DELETE .../navigation_tree/{itemId}

Form Creazione (/functionalities/create?root={rootName})

Layout a due colonne: pannello sinistro (form) + pannello destro (traduzioni).

Sezione INFORMAZIONI GENERALI (sinistra):

  • Nome funzionalità (IT)* — input testo, max 100 caratteri
  • Genitore — dropdown opzionale, lista da GET /configuration/parentList
  • Icona — area drag&drop o file picker, solo SVG; mostra anteprima SVG caricato
  • Descrizione (IT)* — textarea, max 500 caratteri con counter visibile
  • Tags (IT) — tag input: digitare + Invio per aggiungere; tag rimovibili con ×

Sezione IMPOSTAZIONI (sinistra, sotto):

  • Radio button: Categoria / Funzionalità
  • Se selezionato Funzionalità:
    • Tipologia* — dropdown: Pagina incorporata, Link esterno, Funzionalità interna, Permesso, Desktop remoto
    • Link* — input testo

Sezione GESTIONE TRADUZIONI (destra):

  • Accordion per lingua: INGLESE (EN) aperto, ITALIANO (IT) aperto, TEDESCO (DE), FRANCESE (FR), SPAGNOLO (ES), OLANDESE (NL) chiusi
  • Per ogni lingua: Nome funzionalità, Descrizione, Tags

Pulsante "Crea funzionalità" in alto a destra — disabilitato finché i campi obbligatori non sono validi. Al click: POST /configuration/navigation_tree/item → redirect alla lista.

Form Modifica (/functionalities/{funcId}/edit)

  • Stesso layout del form di creazione, pre-popolato con i dati da GET /configuration/navigation_tree/{funcId}
  • Al salvataggio: PATCH /configuration/navigation_tree/{funcId}
  • Pulsante "Salva modifiche" al posto di "Crea funzionalità"

  • Toolbar: Search input, "Colonne" (selettore colonne), "Filtri", pulsante "Nuovo ruolo" (primario)

  • Input: "Nome ruolo" (testo, required)
  • Pulsanti: "Annulla" | "Crea nuovo ruolo" (disabilitato se input vuoto)

Pagina Dettaglio Ruolo (/rolesPermissions/{roleId})

  • Breadcrumb: "Ruoli & permessi / Dettagli"
  • Header: "#{id} {roleName}" + "{N} Utenti associati"
  • Icona matita ✎ accanto al nome del ruolo — visibile solo se roleType = SERVICE — apre modal di rinomina
  • Pulsanti:
    • In modalità visualizzazione: pulsante "Modifica" (disabilitato se roleType = SYSTEM, con tooltip)
    • In modalità modifica: pulsanti "Annulla" e "Salva"
  • Tabs: una per ogni root dell'albero — "Sezioni" (ROOT), "Operazioni" o nome root aggiuntive (OPERATIONS)

PermissionsTree (albero dei permessi)

  • Albero gerarchico dei nodi, uno per riga con indentazione
  • Ogni riga ha un toggle switch a destra: acceso (scuro) = ruolo ha accesso, spento (grigio) = nessun accesso
  • In modalità visualizzazione: toggle disabilitati (non cliccabili)
  • In modalità modifica: toggle cliccabili; il cambiamento viene registrato in un map locale changedAuthorizations
  • Categorie: espandibili/collassabili con la freccia — il toggle della categoria abilita/disabilita anche tutti i figli
  • Al click "Salva" → PUT /role/{roleId} con il solo array degli item modificati
  • Al click "Annulla" → la map viene svuotata, si torna in modalità visualizzazione

Autenticazione & Autorizzazione

Schema generale

  • Tutti gli endpoint delle 3 aree richiedono un JWT Bearer Token nell'header Authorization: Bearer <token>
  • Il token viene emesso da un IDP esterno (es. Keycloak, Auth0). Il backend lo valida e ne estrae il sub (subject)
  • Al primo login l'utente viene sincronizzato nel DB via POST /user/sync
  • Le 3 aree richiedono che l'utente abbia il ruolo Administrator (id=1). Il backend verifica questa condizione su ogni endpoint
  • Se l'utente non ha il ruolo Administrator → risposta 403 Forbidden

Regole di editabilità per i Ruoli
